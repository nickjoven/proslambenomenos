The Gates

the verification doctrine of this repo, written out as it is enforced — eleven computable predicates on the tree, run serially by make gates, any red blocking the merge. Every statement below is transcribed from the committed gate code; the boxed regexes are verbatim; the three small consoles run the same logic live, in your browser. Reds are theorems; greens are not.

I.The intake law — statuses are computed, never declared

status : Claims → S, S = {refuted, conditional, coincidence‑unruled, proven, argued, verified, reproduced, imported, asserted}
status(c) := Φ(evidence(c), premises(c), numeric_match(c)) — Φ fixed;  recorded(c) ≠ Φ(c) ⇒ red “change the evidence, not the label”
refutation ∈ E(c) ⇒ refuted wins over everything
proof ∈ E(c) ∧ method(comp) ∈ {reimplementation, external} ⇒ proven;  proof alone ⇒ argued prose-grade, attested not enforced; machine: true is disabled until an executor exists (LAW-3)
comp ∈ E(c): method ∈ {reimplementation, external} ⇒ verified;  method = rerun only ⇒ reproduced the same algorithm twice is not independence
citation only ⇒ imported; E(c) = ∅ ⇒ asserted
caps: ∃p ∈ premises(c): status(p) ∉ SETTLED ⇒ conditional,  SETTLED = {proven, verified, imported} argued ∉ SETTLED — an argument settles nothing downstream
numeric_match present ∧ (p ≥ 0.05 ∨ p missing) ⇒ coincidence‑unruled
premise graph acyclic (DFS over premises; a gray→gray edge is a cycle ⇒ red)

II.The message gate — the narrative layer is audited

the banned-vocabulary scanner, verbatim from scripts/check_messages.py:
CONCLUSIVE = re.compile( r"(?i)\b(proves?|proof of|exact(?:ly)?|confirms?|closes?|(?<!-)novel(?!-)|" r"establish(?:es|ed)?|demonstrat(?:es|ed|ion)|definitive(?:ly)?|" r"guarantee[sd]?|settle[sd]|resolve[sd]?|" r"first (?:proof|derivation)|zero free parameters|class 5)\b") TAG = re.compile(r"\[claim ([a-z0-9-]+)\]") SUPPORTING = {"proven", "verified", "refuted"}
hits(m) ≠ ∅ ∧ tags(m) = ∅ ⇒ red conclusive words need a claim to point at
hits(m) ≠ ∅ ∧ ¬∃t ∈ tags(m): status(t) ∈ SUPPORTING ⇒ red LAW-5: at least ONE tag must support; coverage tags of capped claims may ride along
touched(m) ⊈ tags(m) ⇒ red every commit touching claims/<id>.yml carries [claim id] — the narrative cannot silently edit the evidence
note the guard (?<!-)novel(?!-): the vocabulary term checked-novel is not conclusive language (LAW-7); bare novel still is.

try appending [claim weak] — still red (argued does not support) — then [claim good].

III.Statement tripwires — agreement and novelty

the numeric-agreement tripwire, verbatim from scripts/check_claims.py:
NUMERIC_AGREEMENT = re.compile( r"(?i)\b(agrees? with|matches? (?:the )?(?:observed|measured)|" r"within [0-9.]+\s*%|[0-9.]+\s*sigma\b|" r"(?:observed|measured|PDG|Planck 20\d\d)\b.{0,40}\b(?:gives?|value))")
NUMERIC_AGREEMENT(statement) ≠ ∅ ∧ numeric_match absent ⇒ red “the pigeonhole cap is not optional” — a tripwire, not a wall: paraphrase can evade it, and the residual is recorded (F3)
novelty is a state machine: novelty.status ∈ {unchecked, classical, folklore, checked‑novel}
classical ∨ folklore ⇒ citation ≠ “ ”;  checked‑novel ⇒ litcheck = LC‑n ∧ LC‑n ∈ headings(LITCHECKS.md)
unchecked ⇒ NOVELTY_VOCAB ∩ statement = ∅ while unchecked, novelty vocabulary is banned in the statement
NOVELTY_VOCAB = re.compile( r"(?i)\b(novel|original|new result|first (?:proof|derivation)|" r"previously unknown|discover\w*)\b")

IV.The pin law — the gates cannot be edited silently

Covered = scripts/check_*.py ∪ scripts/*.js ∪ scripts/verify/*.py ∪ {run_all.py, tests/run_spec.py} ∪ tests/spec/*.spec ∪ {catalog/_common.py} ∪ kernels/*.py
H : files → {0,1}256, H = SHA‑256;  entrylast : dom(entrylast) → {0,1}256 the final LAWCHANGES.md entry is the pin — every amendment re-pins the whole covered set
∃f ∈ Covered: f ∉ dom(entrylast) ⇒ red new gate, no entry — a new covered file forces a full re-pin
∃f ∈ Covered: entrylast(f) ≠ H(f) ⇒ red edit without an entry
∃f ∈ dom(entrylast): f ∉ tree ⇒ red gate deleted silently
each entry: date ∧ direction ∈ {strengthen, weaken, neutral} ∧ a why.  Amending the law stays legal; amending it without a dated, directed, justified entry does not.

V.Append-only — rulings cannot be unmade quietly

Ledgers = {DECLINED, LITCHECKS, LAWCHANGES, PREDICTIONS}.md
∀L ∈ Ledgers, ∀n: Ln ⊑ Ln+1  — committed history only grows enforced over git log -p: no commit may remove a non-empty line
strictly, ⊑ here is subsequence order (insertions anywhere pass — the union merge driver appends); in practice every legal step appends, so history is prefix-ordered.
an edit = a deletion + an insertion ⇒ still red;  L ∉ tree ∧ history(L) ≠ ∅ ⇒ red a deleted ledger is the strongest possible violation (F1)
residual: the owner can still rewrite local history — closed fully only by a remote with protected history (trust rung 3).

VI.Register, then compute

every P‑n carries, before the attempt runs: expects: ∧ changes‑my‑mind:  — bands fixed at tregister < tcompute
the order is ancestry, not clock time: commit(P‑n heading) ≼anc commit(claim citing P‑n) in the commit DAG an uncommitted claim passes only if its prediction is already committed; the protected remote makes the ordering third-party-attested
scope: post-enactment claim ∧ (numeric_match ∨ novelty = checked‑novel) ⇒ prediction required; post-enactment LC entries carry a prediction: line

VII.The falsifier contract — a check that cannot fail is a restatement

∀v ∈ scripts/verify/*.py: rc(v, clean tree) = 0, re-run on every gate pass cited computational evidence cannot rot silently; new scripts are rostered by the glob
∀ registered mutant m of v: rc(v, m) = 1 ∧ “FAIL” ∈ stdout ∧ Traceback ∉ stderr
rcstdoutstderrverdict (LAW-16)
1“FAIL” or “NOT CONFIRMED”clean counts — the mutant ran and failed
1—Traceback crashed ≠ failing mutant
1no FAIL line— silent nonzero ≠ failure
2anything— usage error (unknown mutant, missing file) ≠ failure
0PASS— a passing mutant is rejected
a settled-by-computation claim citing scripts/verify must name null_system ∧ falsifier (LAW-11), and the falsifier must be one of the claim’s OWN cited scripts LAW-16: no borrowed falsifiers
the lesson underneath: a script for which no failing mutant can be written is restating the claim, not testing it the J² sector error, LC-5; the rc-2 “fails as required” audit, 2026-08-22

VIII.The derive layer — instrument nulls before the run

before a registration commits, for every registered detector d and observable O, three obligations (AGENTS.md item 8) — each learned from a fired clause:
(a) null(d) derived, e.g. a locking detector’s tolerance smear w0 = 2 TOL / slope;  “signal present” ⇔ reading compared against null(d), never a bare floor R-29 on P-32: every “width” read 0.00080 — the smear itself, not a signal
(b) identities(O) checked BEFORE positive controls: any exact constraint (telescoping sums, gauge freedoms, symmetries) making a registered outcome trivial or impossible R-30 on P-33: the coupling terms telescope ⇒ ρ ≡ I identically — no step of any order can live in that observable, by algebra
(c) the search domain argued from bounds (per-step displacement, monotonicity), not typical-case guesses R-26: the 0.6 K/q bracket missed shifted windows; replaced by the rigorous |Ω − ρ| ≤ K/2π + ε, unique crossing by monotonicity
a clause that fires on (a) ∨ (b) ∨ (c) is an instrument failure, not a finding, and costs a re-registration (P-33, P-36 after P-35’s R-33); the checklist spends that cost before the run instead.

IX.Prose carries no load

∀ notes/*.md: lines 1..3 contain <!-- commentary --> ∨ <!-- evidence: p1, …, pn -->
commentary ⇒ no settled-status verdicts (“is proven”, “was refuted”, …) anywhere in the note
evidence ⇒ each pi exists ∧ suffix(pi) ∈ {.py, .js, .json, .ipynb, .yml, .yaml} ∨ (.html under compendium | notebooks) .md is not evidence — prose cannot vouch for prose
and every rule above is itself fixtured red/green in a controlled grammar (LAW-20):
RULE gate.n "label": GIVEN fixture WHEN gate RUNS THEN ACCEPT | REJECT MENTIONING "token" | EQUALS json
a RULE naming a gate that does not exist fails — which is how a new gate is written test-first.

X.What green means

“Green means: every ledger parses and appends legally, every claim’s falsifier runs clean and every registered mutant fails with a FAIL line, every catalog fact recomputes, every pinned hash matches. Green does NOT mean the claims are important or the models are right — it means the corpus says what it did and shows how to check it.” — README, “Verifying this repo”
a green gate is consistency accounting, not truth: statuses derive from recorded evidence, undeclared premises are invisible, and the checker cannot read mathematics.
reds are theorems; greens are not.
